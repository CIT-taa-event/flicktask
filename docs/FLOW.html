Task本部 データの流れ

アプリを使うとき、情報がどこを通ってどこに保存されるかの図です。
大事なのは、「使うとき」に通るのは Cloudflare だけで、GitHub は「直すとき」にしか出てこないことです。

利用者の手元（スマホ・PC・LINE・カレンダー） Cloudflare（アプリ本体とデータ） 外部のサービス（Google・LINE） GitHub（プログラムの保管場所）

1. 使うとき（毎日の流れ）

← 図は横にスクロールできます →

  1. 1タスクの読み書き：画面で追加・変更したものは、まず端末に保存され、すぐに Cloudflare のアプリ本体へ送られます。電波がないときは端末に貯めておき、つながったら送ります。
  2. 2ログイン：「Googleでログイン」は、Google に本人か確かめてもらうだけです。Google に送るのはログインの手続きだけで、タスクの中身は送りません。
  3. 3保存：すべてのデータの本物は、Cloudflare のデータベース（D1）にあります。
  4. 4AI：「AIで分解」を押したときだけ、そのメモを Cloudflare の中の AI に渡します。外の AI 会社には送りません。
  5. 5即時反映：誰かが変更すると、同じアカウントで開いている他の端末に「変わったよ」と知らせ、画面が自動で更新されます。
  6. 6カレンダー連携：Googleカレンダーや iPhone が、決まった URL へ数時間おきに予定を取りに来ます（こちらから送るのではなく、向こうが取りに来ます）。
  7. 7LINE：グループで「やること」などと送ると、LINE のサーバーがアプリ本体に知らせ、アプリ本体が返事を LINE 経由で返します。
  8. 8定期実行：毎朝3時（着手目安日の自動移動・古いデータの掃除）と、月曜10時（LINE の今週のまとめ）に、Cloudflare が自動で動きます。

2. 直すとき（管理者が機能を変えるとき）

← 図は横にスクロールできます →

GitHub はアプリの動作には関係しません。GitHub が止まっても Task本部はふつうに使えます。逆に、GitHub に保存しただけでは本番のアプリは変わらず、npm run deploy をしたときに初めて新しくなります。

3. どこに何が保存されるか

場所保存されるもの消えたら
Cloudflare D1（データベース）タスク・イベント・予定・メモ・ログイン情報（Googleの名前とメール）・LINE連携先・カレンダー連携のURLこれが本物。管理者向けの引継ぎ書「困ったとき」を参照
各端末のブラウザタスクの写し（よく使う範囲だけ）、表示の設定（ダーク・ライトなど）次に開いたとき D1 から取り直すので問題なし
Cloudflare の設定（シークレット）Google と LINE の鍵Google Cloud・LINE Developers で作り直して登録し直す
GitHubプログラムと引継ぎ書（データは入っていない）管理者の PC にある写しから戻せる
Google何も保存しない（ログインの確認だけ）—
LINEグループのトーク履歴（ボットの返事を含む。LINE の中に残る）—
