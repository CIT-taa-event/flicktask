このリポジトリは公開されています。パスワード・合言葉・鍵の値はここに書かないでください（幹部の非公開の引継ぎ資料で管理）。

1. まず知っておくこと（3行）

  1. アプリは Cloudflare という会社のサーバーで、24時間勝手に動いています。普段の管理作業はありません。
  2. 毎日・毎週の自動処理（着手目安日で進行中へ、月曜の LINE まとめ）も、サーバーが勝手にやります。
  3. 管理者が手を動かすのは「何か壊れたとき」「機能を変えたいとき」「年度替わり」だけです。

2. どこに何があるか

すべて 幹部の管理用の共有Googleアカウント で入れるようにしてあります。
大学の組織アカウントは Search Console などが使えないため、管理には組織の制限がない方の共有アカウントを使っています（どちらのアカウントかは非公開の引継ぎ資料に記載）。
アプリへのログイン自体は、普段の共有アカウントで構いません。

サービス何をしているか入り口
Cloudflareアプリ本体・データベース（D1）・自動処理・各種の鍵https://dash.cloudflare.com → Workers & Pages → flicktask
Google Cloud「Googleでログイン」の設定（OAuth クライアント）https://console.cloud.google.com → プロジェクト番号 886333017912 → Google Auth Platform
Google Search Consoleログイン設定に必要な「サイトの持ち主」の証明https://search.google.com/search-console → https://flicktask.junjun-tama.workers.dev/
GitHubプログラムの保管場所（このリポジトリ）https://github.com/CIT-taa-event/flicktask （組織 CIT-taa-event の持ち主は管理用アカウント）
LINE Developers / Official Account ManagerLINE ボット「タスク本部」https://developers.line.biz/console/ ・ https://manager.line.biz/

アプリの URL（junjun-tama.workers.dev）は作った人の名前が入っていますが、変えないでください。
変えると Google のログイン設定・LINE の Webhook・カレンダー連携の登録を全部やり直すことになります。

サーバーに登録してある鍵（値はここに書かない）

Cloudflare の flicktask → 設定 → 変数とシークレット に入っています。

名前何の鍵か作り直す場所
GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRETGoogleでログインGoogle Cloud → Google Auth Platform → クライアント
LINE_CHANNEL_SECRETLINE からの通知が本物かの確認LINE Developers → チャネル基本設定
LINE_CHANNEL_ACCESS_TOKENLINE へ送る許可LINE Developers → Messaging API設定

鍵の登録・入れ替えは、PC のターミナルで npx.cmd wrangler secret put 名前 を実行して値を貼り付けます（5章）。

4. 困ったとき

症状まず確認すること直し方
アプリが開かない・真っ白別のスマホやPCでも同じか / https://www.cloudflarestatus.com に障害が出ていないかCloudflare 側の障害なら待つ。続くなら Cloudflare の flicktask → ログ（Observability）を見る
「Googleでログイン」で失敗するGoogle Cloud のクライアントが消えていないか、Search Console の確認が外れていないかクライアントを作り直したら鍵2つを入れ替える（2章）
LINE ボットが返事しないLINE Developers の「Messaging API設定」で Webhook の「検証」が成功するか失敗するなら LINE_CHANNEL_SECRET が違う。アクセストークンを再発行したら LINE_CHANNEL_ACCESS_TOKEN を入れ替える
月曜の LINE まとめが来ないその週に締切も予定もないと送りません。LINE公式アカウントの無料枠（月200通）が尽きていないか枠は「通知1回 × グループ人数」で減ります。翌月に戻ります
カレンダー連携に反映されないGoogleカレンダーは数時間おきにしか取りに来ません半日待つ。URL が漏れたら「カレンダー連携」→「URLを作り直す」
データを間違って消した消した直後ならアプリの「元に戻す」Cloudflare D1 には過去の時点に戻す機能（Time Travel）があります。README のコマンドと Cloudflare のドキュメントを見ながら、慎重に
有料の請求が来た基本はすべて無料プランの範囲で動いていますCloudflare の「請求」でカードが登録されていないか確認

5. 直したいとき（後任のPCで）

機能を変えたり不具合を直したりするときは、PC に Claude Code（AI のプログラミング助手）を入れて、日本語で頼むのが一番早いです。
このリポジトリには、プログラムと一緒に動作確認用のテスト（tests/）が入っているので、直したあと壊れていないかを確かめられます。

最初の1回だけ（準備）

  1. Node.js（LTS 版）をインストール … https://nodejs.org/
  2. Git をインストール … https://git-scm.com/
  3. Claude Code をインストール … https://claude.com/claude-code
  4. このリポジトリを手元にコピー: git clone https://github.com/CIT-taa-event/flicktask.git
  5. コピーしたフォルダで npm install
  6. 手元用の設定ファイルを作る: .dev.vars.example をコピーして、名前を .dev.vars にする（中身はそのままでOK。本物の鍵は入れない）
  7. 手元のデータベースを作る: npm run db:migrate:local
  8. テスト用のブラウザを入れる: npx.cmd playwright install chromium
  9. Cloudflare に管理用の共有アカウントでログイン: npx.cmd wrangler login（ブラウザで「許可」を押す）
  10. 動作確認: npm test がすべて通れば準備完了（10分ほどかかります）

Windows の PowerShell では npx が安全設定で止められることがあるので、npx.cmd と打ってください。
Claude Code を使うには、Claude の有料プラン（Pro など）か API の契約が必要です。誰の契約で使うかは幹部で決めてください。

直すときの流れ

  1. Claude Code をこのフォルダで開き、「〇〇を△△に変えて。README.md と docs/HANDOVER.md を読んでから」と頼む
  2. 手元で動かして確認（npm run dev → ブラウザで http://localhost:5173 ）
  3. テストを通す（npm test）
  4. データベースの形を変えた場合だけ: npm run db:migrate:remote
  5. 本番に反映: npm run deploy
  6. 本番の確認テスト: BASE_URL=https://flicktask.junjun-tama.workers.dev npx.cmd playwright test
  7. GitHub に保存: git add -A → git commit -m &quot;何を変えたか&quot; → git push

うまくいかなかったら、npm run deploy の前なら本番には影響しません。反映後に問題が出たら、Cloudflare の flicktask → デプロイ から1つ前の版に戻せます。

6. アプリでできること（覚え書き）

  • ホーム: これからの流れ（全イベントの締切の流れ）／やること（イベントごとに折りたたみ。締切1か月以内と、着手目安日1週間以内の未着手）／直近の予定
  • イベント画面: 準備（未着手・進行中・完了のボード、担当別タイムライン）／当日の動き（当日モード）／予定／メモ（昨年の申し送りが横に出る）
  • 着手目安日: その日になると、未着手のタスクは自動で進行中へ（その日に手で戻したものはそのまま）
  • カレンダー: 日付をタップでその日の時間割。空いている時間や「終日」から、イベントに入らない予定も追加できる
  • LINE: 「やること」「今週」、イベント名（一部でも可）で返事。毎週月曜10時に今週のまとめ
  • カレンダー連携: Googleカレンダー / iPhone のカレンダーに本番・予定・締切を表示（ウィジェットにも出る）
  • 過去資料: 終了したイベントを年度ごとに保管。新しいイベントを作るときに引き継げる
